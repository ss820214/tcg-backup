# 0バト 管理者認証移行手順（2026-11-03）

**ゴール**: 管理者ID/PINを公開JavaScriptで比較する方式を廃止し、Firebase Authentication メール/パスワードで管理者本人のUIDを証明する。一般ユーザーの既存PINログイン、ジェム、所持カード、デッキは変更しない。

## 必ず先に読む

- 今まで管理者だった端末・Chromeプロファイルを使うこと。**認証連携までログアウト、サイトデータ削除、匿名ユーザー削除をしない。**
- Firebase Consoleで新しい管理者ユーザーを手作業で追加しない。**既存匿名ユーザーを連携してUIDを保持する**。
- メールアドレスと新しい強力なパスワードはChatGPT・GitHub・スクショに含めない。新パスワードは12文字以上、旧PINは使い回さない。
- 管理者UIDは秘密ではないが、誤ったUIDをFirestoreルールに設定するとカード編集に失敗する。
- 現行FireStoreルールのバックアップを取ること。GitHub HostingのデプロイだけではFirestoreルールは変更されない。

## 手順 1. Firebase Authのメール/パスワードを有効化

1. https://console.firebase.google.com/project/tcg-0bato/authentication/providers を開く。
2. Authentication → ログイン方法 →「メール / パスワード」を有効化して保存する。
3. **「ユーザーを追加」ボタンは押さない。** 先に既存UIDへ連携する。

## 手順 2. 既存管理者の匿名UIDをメール認証へ引き継ぐ

1. これまで管理者としてカードを編集できていた**同じブラウザ**で https://tcg-0bato.web.app/login.html を開く。
2. 画面下「管理者メール認証」欄に、自分のメールと**新しい**パスワードを入力する。
3. 「既存管理者にメールを紐づけ」を押す。
4. 「メール認証の連携成功。UIDを維持できました。」と表示され、UIDが確認できたら成功。**このUIDを控える。**
5. 「メールで管理者ログイン」を押す。ログインに成功してもUIDが同じであることを確認する。
6. ホーム、デッキ、カード工房の管理者表示を確認する。

注意: 「現在の端末のUIDは既存の管理者ではありません」と出たら**新しいアカウントを作らず**、以前の管理者端末に戻る。既存UIDが失われている場合はバックアップからの慎重な復旧が必要。

## 手順 3. FirestoreルールをUID基準に変更（必須）

1. Firebase Console → Firestore Database → ルールを開く。
2. **現行ルール全体をバックアップする。**
3. 既存の `function isAdmin()` **だけ**を以下に入れ替える。全ルールを置き換えない。

```javascript
function isAdmin() {
  return signedIn()
    && request.auth.uid == "ここに手順2の管理者UIDを貼る"
    && request.auth.token.firebase.sign_in_provider == "password";
}
```

4. UIDの左右の引用符を消さず、上の「ここに～」をFirebase Authの管理者UIDに置き換える。
5. **UIDを入力したこと、メールログインできたことを確認してから**公開する。
6. `users/{uid}` の `isAdmin` を一般ユーザーが変更できない既存の防御ルールは維持する。

このルールにした後は、固定PINや匿名認証だけでは管理者のカード編集を認めず、Firebase Authenticationでパスワードログインした**指定UIDだけ**を管理者と扱える。

### おすすめの確認

- 管理者: カード1枚の更新を試し、成功を確認する（削除テストはしない）。
- 一般ユーザー: カードの更新が `permission-denied` になることを確認する。
- 管理者/一般ユーザー双方で、プロフィール・デッキ保存・ガチャ表示・対戦開始を確認する。
- 設定失敗時は**UID・ログインプロバイダ・ルール構文**を先に見直す。従来の平文PIN認証に戻さない。

## 現時点の制限

- Firestoreのルール変更とメール/パスワード有効化はFirebase Console側の手動操作であり、Hostingコードのデプロイに含まれない。
- 今回の主眼は管理者PINの撤去。Firestoreの `decks` に残る管理者付与指示や `users` のジェム/所持カードの更新制限は**別途強化が必要**。
- 初期登録で既存UIDを引き継げなかった場合、UIDが変わると所持品のデータは別アカウントになるので、紐づけに失敗したからといって新規管理者ユーザーを作らない。
