# v1.2.2 — 公開前の動作整備（2026-11-16）

## 実装

- PLAY・待機室の入室処理を共通化。人数確認、部屋と参加者の登録を1トランザクションにまとめ、同時参加でも2枠までに制限。
- 同じUIDの再入室は既存の参加枠・デッキ・READYを維持。ソロ・満員・開始済み・期限切れ・退出で閉じた部屋への新規参加を拒否。旧デッキ画面の開始ボタンもPLAYへ集約。
- 待機室に明示的な退出を追加。ホスト退出時は部屋を閉じる。画面消灯やページの破棄では参加枠を削除しない。
- マッチ作成時に対象2人のREADYをトランザクションで再確認し、開始時のデッキ・EX・参加者UIDを記録。勝者デッキはこの記録を優先し、後から編集した内容に変化しない。
- 別タブでアカウントが切り替わった場合、前のUIDで開いた対戦の人間・CPU操作を拒否する。
- 通信がキャッシュのみの状態では操作を受け付けず、再接続でサーバーの盤面を取得してから操作を再開。PLAYに前の対戦・待機へ戻る入口を追加。
- 開始演出・結果画面で認証復元後にFirestoreを読む。開始演出の状態参照パスを実際の対戦パスへ修正。
- 一般プレイヤー向けのメール連携・別端末での再開を追加。リンクではUIDを維持。ログインはメモリ上の別Authで事前確認し、誤った資格情報で現在のUIDを置き換えない。ID・PINは端末内の確認用と明記。
- 初期カード30枚の練習デッキを追加。編集中デッキは明示的な切替確認とローカルの控え・復元ボタンで保護。
- 結果URLの値だけで報酬を決めず、保存された試合・盤面の勝者・参加者UIDを照合。未決着・他人の席・偽の勝敗では報酬処理を実行しない。

## 検証

- `v122_readiness_regression.mjs`: 楽観的トランザクションの競合・リトライを模擬し、同時参加で1人だけが残り枠を確保すること、再入室・退出・各拒否条件を検査。デッキ、報酬照合、メール切替失敗時のUID保持、通信状態の検査を含む。
- 独立したセッションの匿名Authを使い、通常UIから2人分のFirestore対戦を実行。QA用アカウント名はQA122_HOST／QA122_GUEST／QA122_THIRD。QAではAuth永続化だけをタブ単位へ変更し、実アプリのルーム・対戦処理を利用。
- 3人目の満員拒否、開始後の参加拒否、同じ参加者での待機室再読み込み、双方の準備完了→対戦開始を確認。
- 召喚後のユニット・消費マナを双方で確認。対戦画面を再読み込みして同じ盤面・担当側・マナを復元し、その後双方のターン終了が同期することを確認。
- QA用のUIからFirestore Web SDKの通信を停止。未同期中のターン終了クリックでは両側のターンが変化せず、通信再開後のクリックだけが対戦へ反映されることを確認。
- 待機室からホスト退出後、対戦準備へ戻ることを確認。PLAYの「前の対戦に戻る」から元の試合へ再開できることも実クリックで確認。
- 新しい入室処理からCPU戦を作成し、READY→開始演出→対戦画面の初期同期も確認。開始演出の権限エラーは再発しなかった。
- メール連携は資格情報を模擬したテスト。実メールの登録・新規パスワード設定はユーザー操作が必要。Firebase Authenticationのメール／パスワードが有効であることが運用条件。
- Android実機の画面消灯や携帯網切替は未検証。ブラウザ上の独立セッションとSDKの通信停止・再開を検証したもので、実機2台の検証と混同しない。

- 対戦準備・引き継ぎ画面を390px／320px幅で確認。横はみ出しなし。52件の公開前構文／回帰検査を実行。
